# Finding and using design inspiration

Read for substantial design work when the visual direction is open. Scale research to uncertainty; stop when the references support a useful decision. Routine changes to an established UI usually need no new search.

## Search with a purpose

Start with the project's audience, primary job, and constraints. Form queries around the needed experience, such as appointment-booking navigation, dense inventory tables, or multilingual museum reading layouts. Identify what needs inspiration: a flow, information hierarchy, visual identity, or specific component.

Start with a few relevant shipped products, often two or three, rather than surveying the web. When it improves the direction, include a contrasting product or a non-UI source such as editorial typography, signage, packaging, or the subject's visual culture. Consider the audience's market and language where relevant.

Use live product pages and public demos for operational patterns. Curated galleries, including Awwwards, SiteInspire, or Land-book, can help discover visual approaches; Dribbble and Behance concepts can offer visual ideas. Treat gallery concepts as aesthetic references, not evidence that a flow works or is accessible. These are optional starting points, not a prescribed source list or style catalog.

## Inspect rather than infer

Browse available pages and inspect screenshots or supplied images. For navigation and interaction lessons, exercise the relevant flow when accessible and within authorization. Search snippets and promotional descriptions do not establish how an interface actually looks or behaves.

Record the URL or local image path, what was inspected, and the transferable lesson. A compact note is enough: reference / observed principle / relevance / limitation. Distinguish observed behavior from inference; do not claim to have verified responsiveness, accessibility, or conversion outcomes from a static screenshot.

If a reference requires unavailable access, use another public reference or explain the limitation. If visual inspection is unavailable, label the direction as provisional instead of presenting unverified research as evidence.

## Synthesize rather than clone

Combine useful principles from the references with the project's constraints. For example, adopt a clear grouping approach from one product and readable information density from another, while preserving the project's own tokens and components. Do not copy an entire site's composition, branding, text, or assets. Reference images are inspiration, not automatically licensed production assets.

Recommend a direction tied to user needs, with a short alternative when uncertainty warrants it. Name what each reference contributes and what does not fit this project. Do not choose a fixed aesthetic from a global list or map an industry automatically to a palette.

Check for habits: are colors, fonts, card shapes, or opening layouts being reused from earlier work without justification? Use available relevant history as a prompt to reconsider, not a reason to search every past project or force difference for its own sake.

Keep the output compact: a few reference links and lessons, the recommended direction, and the main tradeoff. Use a moodboard—a small annotated collection of visual references—only when it would help the user review the direction. Then translate the chosen principles into this project's shared foundation and representative screen.
